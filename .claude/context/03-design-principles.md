# Design Principles

These principles guide decisions for the design system and the portfolio it builds. They describe what the experience should feel like — for visitors to the portfolio, and for Adam using the system to build and maintain it.

## 1. The work is the hero

The portfolio exists to showcase case studies, not to demonstrate web design skill. Every layout decision should direct attention toward the work. When the site design is working well, it should be almost invisible.

This means restraint: no decorative elements that compete with content, no transitions that delay access to information, no layouts that make the designer look clever at the expense of the work looking good.

## 2. Precision over polish

Adam's technical leaning isn't just a bullet point — it's a design value. Every decision in this system should be purposeful and explainable. A well-reasoned spacing scale matters more than a beautiful gradient. If a token can't be justified, it probably shouldn't exist.

This guides the feel of the entire system: systematic over decorative, structured over expressive, considered over trendy.

## 3. Designed for scanning, built for reading

Marcus spends 30 seconds deciding whether to stay. Priya reads for 20 minutes if the work earns it. The design must work for both.

Strong typographic hierarchy for quick scanning. Comfortable reading rhythm for sustained attention. Information should surface the right things at the right moment — not front-load everything, and not hide what matters.

## 4. Craft is the argument

The portfolio is making a claim: this person is a skilled, senior designer. The site design is evidence for or against that claim before anyone reads a word.

Inconsistent spacing, arbitrary type sizes, or sloppy colour choices undermine the work that follows. The design system exists to make it impossible for the execution to contradict the claim.

## 5. Honest over impressive

The portfolio should feel like a real person's work, not a performance. Restraint where restraint is right, personality where personality serves the content. No trend-chasing; every decision should still feel right in two years.

This is especially important for Yemi and Priya — both can spot the difference between a portfolio that's trying hard and one that's sure of itself.

## 6. One voice, everywhere

The same aesthetic sensibility should run through the homepage, case study pages, and contact. Consistency at this level signals systems thinking — which is core to Adam's positioning, and exactly what this design system is here to demonstrate.

## 7. The process is a deliverable

This system was built by one person using Figma and Claude Code as primary tools. That workflow — AI-assisted design system construction, token pipelines, component documentation — is itself a case study.

Every decision in the system should be legible to someone reading it as a portfolio piece. The Figma file, the code, and the component sheets should all tell a coherent story about how the system was made, not just what it produces.
